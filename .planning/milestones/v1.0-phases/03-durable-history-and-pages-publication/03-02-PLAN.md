**pages/index.html:**

Create a single static HTML file that serves as the benchmark dashboard. This file will be copied to the gh-pages branch root during deployment. It must work when served from GitHub Pages (not local filesystem).

Structure:
- Title: "SOL Benchmark History"
- Load Chart.js v4.4.1 from jsdelivr CDN (pinned version, NOT @latest)
- On load, fetch `history/index.json` and `baseline-active.json`
- Sort runs by timestamp ascending

Overview section:
- Display 4 trend line charts (one per key metric): throughput_blocks_s, init_time_s, avg_per_block_ms, peak_rss_mib
- X-axis: run timestamps (short date format)
- Each chart loads per-run JSON files via fetch() to get metric values
- Highlight the active baseline run on charts (e.g., different point style or vertical annotation)
- Show run count, latest run date, and active baseline info in a header summary

Drill-down:
- Below the overview charts, render a table of all runs with columns: date, commit (short SHA linked to GitHub), profile, metrics, active baseline indicator
- Clicking a run in the table shows its full detail (provenance, environment, all metrics) in an expandable section or modal

Styling:
- Clean, minimal CSS (inline in the HTML, no external stylesheets)
- Responsive layout (works on desktop and mobile)
- Use a simple color scheme: dark text on light background, chart colors from Chart.js defaults

Error handling:
- If fetch fails (no history yet), show a "No benchmark history available" message
- If baseline-active.json is missing, omit baseline highlighting gracefully

Include a comment noting that local testing requires `python3 -m http.server` in the gh-pages branch checkout.

**sol-pages-deploy.yml (new workflow):**

Create a reusable deployment workflow using the official GitHub Pages pipeline:
- Triggered by: `workflow_call` (so other workflows can invoke it) and `workflow_dispatch` (manual trigger)
- Permissions: pages: write, id-token: write, contents: read
- Environment: github-pages

Two jobs:
1. **build**: checkout gh-pages branch, copy pages/index.html from main branch (or use a step to fetch it), run `actions/configure-pages@v5`, run `actions/upload-pages-artifact@v3` with path '.' (entire branch root = site)
2. **deploy**: needs build, run `actions/deploy-pages@v4`, output page_url

Approach for getting index.html to gh-pages: The simplest approach is to have the build job checkout gh-pages (which has history/ and baseline-active.json), then checkout just pages/index.html from main branch using `git checkout origin/main -- pages/index.html && cp pages/index.html ./index.html`. This puts the dashboard HTML alongside the data files.
