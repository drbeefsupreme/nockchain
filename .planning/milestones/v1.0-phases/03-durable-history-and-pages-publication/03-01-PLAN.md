<task type="auto">
  <name>Task 1: Create sol_history_append.sh and per-run JSON generation</name>
  <files>scripts/sol_history_append.sh</files>
  <action>
Create `scripts/sol_history_append.sh` following the existing project Bash conventions (set -euo pipefail, consistent with sol_baseline_run.sh style).

The script takes 3 required arguments:
1. MANIFEST_JSON — path to meta/manifest.json from the baseline run
2. SUMMARY_TSV — path to data/combined_summary.tsv from the baseline run
3. PUBLISH_DIR — empty directory where output files are written

And reads existing index.json content from stdin or a 4th argument (defaults to '[]').

Script logic:
1. Compute RUN_ID: read timestamp from manifest, replace colons with dashes, append underscore + first 7 chars of git_commit. Format: `2026-02-26T08-00-00Z_abc1234`.
2. Compute metric medians from the TSV. Use column-name lookup (not hardcoded positions) for safety:
   - For each target metric (throughput_blocks_s, init_time_s, avg_per_block_ms, peak_rss_mib), find column index from header row using awk.
   - Extract that column for all data rows, sort numerically, pick the middle value (median).
   - Handle single-row case (median = that row's value).
3. Build per-run JSON with jq containing: run_id, timestamp, git_commit, git_branch, profile, passes (count of data rows), metrics object (4 median values), environment object (cpu_model, cpu_cores, ram_bytes from manifest).
4. Write to PUBLISH_DIR/{RUN_ID}.json.
5. Read existing index.json (from 4th arg or default empty array), append new entry with fields: run_id, filename, timestamp, git_commit, git_branch, profile, is_active_baseline=false. Write to PUBLISH_DIR/index.json.

Make the script executable (chmod +x).

Do NOT include the entire history directory in PUBLISH_DIR — only the new run JSON and updated index.json. This is critical to avoid overwriting existing history files when peaceiris/actions-gh-pages pushes with keep_files: true.
  </action>

**sol-baseline.yml changes:**

1. Add `contents: write` to permissions (currently `contents: read`) — needed for peaceiris action to push to gh-pages branch.
2. Add `pages: write` and `id-token: write` permissions for future Pages deploy integration.
3. Add a concurrency group to serialize history writes:
   ```yaml
   concurrency:
     group: bench-history-write
     cancel-in-progress: false
   ```
4. After the existing "Save baseline reference cache" / "Cache baseline reference" steps, add two new steps (run on ALL triggers, not just push to master):

   a. "Build history payload" step:
      - `mkdir -p history-payload`
      - Fetch existing index.json from gh-pages branch: `git fetch origin gh-pages 2>/dev/null; EXISTING_INDEX=$(git show origin/gh-pages:history/index.json 2>/dev/null || echo '[]')`
      - Run: `bash scripts/sol_history_append.sh bench-artifacts/sol-baseline/latest/meta/manifest.json bench-artifacts/sol-baseline/latest/data/combined_summary.tsv history-payload "$EXISTING_INDEX"`

   b. "Push to history branch" step:
      ```yaml
      uses: peaceiris/actions-gh-pages@v4
      with:
        github_token: ${{ secrets.GITHUB_TOKEN }}
        publish_dir: ./history-payload
        publish_branch: gh-pages
        destination_dir: history
        keep_files: true
        commit_message: "history: run ${{ github.sha }} (${{ github.run_number }})"
      ```

**sol-advance-baseline.yml (new file):**

Create a workflow_dispatch-only workflow for baseline advancement:
- Input: `run_id` (required string, description: "Run ID to promote, e.g. 2026-02-25T12-00-00Z_abc1234")
- Permissions: contents: write, pages: write, id-token: write
- Concurrency group: bench-history-write (same group, cancel-in-progress: false)
- Single job "advance" on ubuntu-latest:
  1. Checkout gh-pages branch (fetch-depth: 1)
  2. Validate step: confirm `history/${{ inputs.run_id }}.json` exists, validate with `jq -e '.git_commit and .timestamp and .metrics'`
  3. Write baseline-active.json with jq: run_id, promoted_at (UTC ISO), git_commit (read from run file), promoted_by: "workflow_dispatch"
  4. Update history/index.json: set is_active_baseline=false for all entries, then set is_active_baseline=true for the promoted run_id
  5. Build a publish directory containing only baseline-active.json and updated history/index.json
  6. Push via peaceiris/actions-gh-pages@v4 with keep_files: true, commit_message: "baseline: advance to ${{ inputs.run_id }}"

CRITICAL: Always use `keep_files: true` on every push to the history branch. Never omit it.
