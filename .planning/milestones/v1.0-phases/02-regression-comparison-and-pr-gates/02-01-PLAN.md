**In model.rs — add new types (do NOT modify existing types):**

1. Add `ComparisonVerdict` enum with four variants: `Improvement`, `Regression`, `NoSignificantChange`, `Inconclusive`. Derive `Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize` with `#[serde(rename_all = "snake_case")]`.

2. Add `MetricDirection` enum: `Higher` (higher is better, e.g. throughput), `Lower` (lower is better, e.g. latency/memory). Same derives.

3. Add `ComparisonResult` struct with fields:
   - `metric: CanonicalMetric`
   - `verdict: ComparisonVerdict`
   - `candidate_value: f64`
   - `baseline_median: f64`
   - `baseline_mad: f64`
   - `delta_pct: f64` (percentage change: (candidate - baseline) / baseline * 100)
   - `delta_abs: f64` (absolute change: candidate - baseline)
   - `confidence: f64` (1.0 - alpha, e.g. 0.90)
   - `baseline_samples: usize`
   - `reason: String`

4. Add `ComparisonReport` struct with fields:
   - `results: Vec<ComparisonResult>`
   - `overall_verdict: ComparisonVerdict` (worst verdict across metrics — Regression > Inconclusive > NoSignificantChange > Improvement)
   - `candidate_source: String` (path or label for candidate TSV)
   - `baseline_source: String` (path or label for baseline TSV)
   - `baseline_total_samples: usize`
   - `significance_threshold: f64` (the alpha used, default 0.10)

5. Add `ComparisonConfig` struct with fields:
   - `significance_threshold: f64` (default 0.10 for ~90% confidence)
   - `min_samples: usize` (default 3 — below this, verdict is Inconclusive)
   - `bootstrap_iterations: usize` (default 500)
   - `bootstrap_seed: u64` (default 42 for determinism)
   - `metric_overrides: BTreeMap<String, MetricOverride>` (per-benchmark threshold overrides, keyed by metric name)

6. Add `MetricOverride` struct: `significance_threshold: Option<f64>`, `min_samples: Option<usize>`.

7. Implement `Default` for `ComparisonConfig` with the defaults above.

8. Add a `metric_direction()` method on `CanonicalMetric` that returns `MetricDirection`:
   - `Higher` for `ThroughputBlocksS`
   - `Lower` for `InitTimeS`, `TotalPokeTimeS`, `AvgPerBlockMs`, `PeakRssMib`, `P95RssMib`, `MinorFaultsDelta`, `MajorFaultsDelta`, `FailedPokes`
   - `Lower` for `Checkpoints` (fewer is better for overhead; treat as neutral/lower)
   - `Lower` for `ExitStatus` (0 is success)

**In compare.rs — create new module:**

1. Import `bootstrap_median_ci`, `median`, `mad` from `super::stats`, types from `super::model`, and `parse_combined_summary_tsv` from `super::ingest`.

2. Implement `classify_verdict(candidate_ci: ConfidenceInterval, baseline_ci: ConfidenceInterval, direction: MetricDirection, actual_samples: usize, min_samples: usize) -> ComparisonVerdict`:
   - If `actual_samples < min_samples` → `Inconclusive`
   - Check CI overlap: `candidate_ci.low <= baseline_ci.high && baseline_ci.low <= candidate_ci.high`
   - If overlap → `NoSignificantChange`
   - If no overlap, check direction: `candidate_ci.low > baseline_ci.high` means candidate is above baseline
   - For `MetricDirection::Higher`: candidate above = `Improvement`, candidate below = `Regression`
   - For `MetricDirection::Lower`: candidate above = `Regression`, candidate below = `Improvement`

3. Implement `compare_metric(metric: CanonicalMetric, candidate_values: &[f64], baseline_values: &[f64], config: &ComparisonConfig) -> ComparisonResult`:
   - Get effective threshold and min_samples (check `config.metric_overrides` for the metric name, falling back to config defaults)
   - Compute `baseline_med = median(baseline_values)`, `baseline_mad_val = mad(baseline_values, baseline_med)`
   - Compute `candidate_med = median(candidate_values)`
   - Compute bootstrap CIs for both candidate and baseline using `config.significance_threshold` as alpha
   - Compute `delta_pct` and `delta_abs`
   - Call `classify_verdict`
   - Build reason string explaining the classification
   - Return `ComparisonResult`

4. Implement `run_comparison(candidate_tsv: &Path, baseline_tsv: &Path, config: &ComparisonConfig) -> Result<ComparisonReport, ComparisonError>`:
   - Parse both TSVs using `parse_combined_summary_tsv`
   - Group values by `CanonicalMetric` — for each metric, collect all candidate values and baseline values from the parsed rows
   - For each metric present in either set, call `compare_metric`
   - Compute `overall_verdict` as the worst across all results
   - Return `ComparisonReport`

5. Define `ComparisonError` enum: `IoError`, `ParseError`, `NoMetrics`.

**In compare_report.rs — create new module:**

1. Implement `render_comparison_markdown(report: &ComparisonReport) -> String`:
   - Title: `## SOL Benchmark Regression Report`
   - Compact summary table: `| Benchmark | Verdict | Effect | Confidence |` with one row per metric
   - Verdict icons: Improvement = `🟢 improvement`, Regression = `🔴 regression`, NoSignificantChange = `✅ no change`, Inconclusive = `❓ inconclusive`
   - Effect column: `{delta_pct:+.1}%` format (signed, one decimal)
   - Confidence column: `{confidence*100:.0}%` or `—` for inconclusive
   - `<details><summary>Per-benchmark statistical detail</summary>` section with per-metric breakdown:
     - Candidate value, baseline median, MAD, sample count
     - Delta absolute and percentage
     - Bootstrap CI ranges
     - Verdict with reason
   - Footer: `> Advisory only — this check does not block merge.`
   - Footer: `> Baseline: {baseline_source} ({baseline_total_samples} samples)`

2. Implement `render_comparison_json(report: &ComparisonReport) -> Result<String, serde_json::Error>`:
   - Serialize `ComparisonReport` as pretty-printed JSON using serde_json

3. Implement `write_comparison_markdown(path: &Path, report: &ComparisonReport) -> Result<(), ReportError>` and `write_comparison_json(path: &Path, report: &ComparisonReport) -> Result<(), ReportError>` following the same `ReportError` pattern from `report.rs`.

**In main.rs — add Compare subcommand to SolCommands enum:**

Add a `Compare` variant to `SolCommands` (following the existing `Guard` pattern):
```
Compare {
    /// Candidate combined summary TSV
    #[arg(long)]
    candidate_summary: PathBuf,

    /// Baseline combined summary TSV
    #[arg(long)]
    baseline_summary: PathBuf,

    /// Significance threshold (alpha), default 0.10 for ~90% confidence
    #[arg(long, default_value = "0.10")]
    significance: f64,

    /// Minimum baseline samples before declaring inconclusive
    #[arg(long, default_value = "3")]
    min_samples: usize,

    /// Output JSON delta file path
    #[arg(long)]
    output_json: Option<PathBuf>,

    /// Output Markdown summary file path
    #[arg(long)]
    output_md: Option<PathBuf>,
}
```

Add the match arm in the `SolCommands` dispatch (near the existing `SolCommands::Guard` arm):
- Build `ComparisonConfig` from CLI args (significance, min_samples, defaults for rest)
- Call `run_comparison(&candidate_summary, &baseline_summary, &config)`
- If `output_json` is Some, call `write_comparison_json`
- If `output_md` is Some, call `write_comparison_markdown`
- Always print the Markdown summary to stdout
- Exit with code 0 (advisory only — never fail the process per user decision)
